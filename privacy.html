LM Private Drive privacy policy

Last updated: 24 September 2026.

Purpose and contact

LM Private Drive is operated by the integration administrator reachable at jxcj16@gmail.com. It connects an authorized leave-management application to a designated Google Drive account for managing leave-proof documents.

Information processed

The integration processes the connected Google account’s identity and authorization tokens, leave-proof file contents, employee numbers, leave-request identifiers, application timestamps, approval statuses, file references, and checksums. Proof documents may contain personal, employment, or health-related information supplied through the leave-management application.

How information is used

Information is used to authenticate the connection, check access to leave requests, upload and retrieve proof files, verify file integrity, recover interrupted transfers, and organize the same files in folders according to application date and status. The integration requests the Google Drive drive.file scope, which limits its access to files it creates or that are explicitly authorized for the app.

Storage and access

Proof files are stored in the designated Google Drive account. Supabase hosts the private integration backend and stores connection and file-mapping metadata; refresh tokens are encrypted before storage. The leave-management application retains request information and file references. During migration, original files may remain in the application’s existing storage until the operator verifies the replacement and authorizes removal.

Google and Supabase process data to provide these services. Access to stored files depends on the Drive account’s sharing permissions; application access depends on authenticated leave-management permissions. Administrators who control the associated accounts and infrastructure may have administrative access. This integration does not automatically make Drive proof files public.

Retention and requests

The integration does not currently implement automatic file or metadata expiry. Files and metadata remain until an authorized administrator removes them, subject to the storage providers’ retention and recovery behavior. Contact the integration administrator to request access, correction, or deletion. Employment-record retention obligations may affect whether and when records can be removed.

Disconnecting Google

The Google account holder can revoke the app’s authorization through Google Account permissions. Revocation stops further authorized API access after existing access tokens expire; it does not itself delete files already stored in Drive or metadata already stored by the integration. Contact the administrator for deletion requests.

Google API data

The integration uses Google API data for the document-management functions described above. Its code does not implement advertising, sale of Google user data, or AI model training. Use of information received from Google APIs is subject to the Google API Services User Data Policy, including its Limited Use requirements.

Scope of this policy

This policy covers LM Private Drive. The employer’s leave-management policies and the policies of Google and Supabase also govern their respective services and records.
